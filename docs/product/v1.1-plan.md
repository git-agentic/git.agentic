# git.agentic v1.1 — Plan

**Status:** Draft v0.1
**Date:** 2026-05-21
**Owner:** Toni
**Predecessor:** [`mvp-spec.md`](./mvp-spec.md) (v1.0, target 2026-08-11) and [`roadmap.md`](./roadmap.md) §"Out of scope for the 12 weeks"

This is **not** the full v1.1 plan. It is the slice of v1.1 work that comes directly out of:

- the Code.Storage assessment (May 2026) — managed Git-infra is real enough that we need a clean trait shape to either consume it as a backend or ignore it without re-litigating;
- the Entire CLI competitive assessment (May 2026) — see [`competitive-brief-entire.md`](./competitive-brief-entire.md). Three patterns worth borrowing (secondary `ObjectStore` per ADR-0008, narrative summarization per ADR-0009, multi-agent hook installer matrix); their positioning explicitly not borrowed; and
- the natural follow-ups from [ADR-0002](../adr/0002-substrate-and-supercommit.md) Decision 6, [ADR-0005](../adr/0005-sessionstore-amendment-to-adr-0004.md), and the hardening sprint's exposed gaps.

The broader v1.1 (Mem0/Zep/Letta adapters, CrewAI/AutoGen integrations beyond the deferred hook-installer skeleton, web UI, hosted SaaS) is tracked separately under [`roadmap.md`](./roadmap.md) §"Out of scope" and gets its own plan once v1.0 ships. **Nothing in this document is permitted to compromise the v1.0 broken-prompt demo or the 2026-08-11 ship date.**

## What this plan covers

Four workstreams, all opening immediately after the v1.0 demo lands:

1. **Storage backend matrix** — formalised `ObjectStore` trait, S3 backend, managed-Git adapter pattern. Governed by [ADR-0006](../adr/0006-objectstore-backend-trait.md).
2. **Ephemeral branches as a primitive** — first-class ref namespace, lifecycle, promotion gesture, GC. Governed by [ADR-0007](../adr/0007-ephemeral-branches-agent-run-primitive.md). Rehomes ADR-0005's per-session branches.
3. **Hardening rollover** — the items the 2026-05-20 hardening sprint surfaced that don't fit v1.0 scope but are not v2+: GC for blob-level orphans, filesystem-snapshot-capability enforcement (the v1.0 informational warning becomes a hard guard, per ADR-0002 Decision 4), production-readiness validation against real GCS (concurrent writers, partial-upload failure injection, service-account auth, large-blob streaming).
4. **Surface-parity with Entire-class tooling (Entire-derived).** Three sub-pieces, each cheap individually: secondary `ObjectStore` for the OSS-with-private-agent-state and regulated-tier cases ([ADR-0008](../adr/0008-secondary-objectstore-for-agent-state.md)); commit-time narrative summarization populating the dormant `Commit.intent` and new `Commit.narrative` fields ([ADR-0009](../adr/0009-commit-time-narrative-summarization.md)); and a deferred multi-agent hook-installer matrix skeleton (verb + file-location convention only, no agent-specific impls) so the second framework integration after Executor doesn't reinvent the wheel.

What this plan explicitly **does not** cover:

- Mem0 / Zep / Letta memory backends. They're v1.1 but live behind the `MemoryAdapter` trait, not this plan. Separate doc when a design partner pulls one.
- CrewAI / AutoGen / LlamaIndex framework integrations. Same — behind the framework-neutral SDK contract from [ADR-0003 Decision 3](../adr/0003-claude-agent-sdk-integration.md), separate plan when pulled.
- Web UI / agent-PR review primitive. v1.1 product surface per [ADR-0002 Decision 6](../adr/0002-substrate-and-supercommit.md); not in this plan because it isn't on the substrate path.
- Hosted SaaS. Post-seed per [`roadmap.md`](./roadmap.md).
- Per-hunk attestation, multi-agent commit graphs. v2+ per [ADR-0002 Decision 6](../adr/0002-substrate-and-supercommit.md).

## Strategic framing

Two pressures shape what v1.1 must absorb without distortion.

**The platform-led GTM lane is real.** ADR-0002's extended Commit object commits us to the substrate-level shape of "the git host built for when most commits are written by agents." Pierre's Code.Storage and any equivalent that emerges are commercial precedent that the lane exists. v1.1 does not enter that lane as a product (we don't ship hosted SaaS), but the trait and ref-model shape we ship in v1.1 must be compatible with eventually doing so — and compatible with consuming managed-Git providers as backends if a design partner already lives on one.

**The MVP scope discipline must survive past 2026-08-11.** The reason v1.0 is going to ship is the demo-as-discipline rule. v1.1 inherits the same risk surface: scope creep dressed as "obvious next step." This plan limits itself to the minimum shape that lets us say yes-or-no to the next design-partner ask without re-architecting. Anything that turns into a multi-month thread before a partner asks gets deferred again.

## Success criteria

A v1.1 release is shippable when **all** of these are true:

1. The `ObjectStore` trait has `delete`, `list_prefix`, and an `AsyncObjectStore` variant. `FsObjectStore` and `GcsObjectStore` implement both surfaces. One additional backend ships — either `S3ObjectStore` or a `ManagedGitStore` adapter, chosen by which design partner pulls first.
2. Ephemeral branches are a first-class primitive. `agentic promote`, `agentic ephemeral seal|discard|retain|list`, and TTL-based GC all work end-to-end. ADR-0005's `executor/<session_id>` lives at `refs/ephemeral/executor/<session_id>`.
3. Blob-level GC works against `FsObjectStore` and `GcsObjectStore`. A repository idle for the documented TTL window reclaims orphan blobs without manual intervention.
4. The ADR-0002 Decision 4 "filesystem snapshot-capable storage" warning has been upgraded to a hard guard for production deployments (the MVP-grade informational warning stays as the default for the demo path).
5. The GCS production-readiness validation work from the hardening sprint's "explicitly not gated by the kill-criterion" list is closed: concurrent-writer tests, partial-upload failure injection, service-account auth, and large-blob streaming all green.
6. Two design partners are using v1.1 against a non-`FsObjectStore` backend in their own staging or production. (One is permitted if the second slot is genuinely blocked on customer procurement; do not lower the bar to zero.)
7. Secondary `ObjectStore` ([ADR-0008](../adr/0008-secondary-objectstore-for-agent-state.md)) is shippable: `RoutedObjectStore` lands, `[object_store.secondary]` config + token env vars work end-to-end against at least `FsObjectStore` (primary) + `GcsObjectStore` (secondary) and at least one `ManagedGitStore` adapter. `required = true` loud-fail mode is exercised by failure-injection tests against the extended 2PC staging order.
8. Commit-time narrative summarization ([ADR-0009](../adr/0009-commit-time-narrative-summarization.md)) ships behind a default-off opt-in. `Commit.narrative` field populated; `Commit.intent` no longer always `Hash::ZERO` when summarization is enabled. Successor-commit-as-amendment pattern works with `expect_parent` race-free ref-write. `anthropic_api` and `claude_cli` providers both implemented; `none` provider with manual `agentic commit amend-narrative` works.
9. Multi-agent hook-installer matrix skeleton: `agentic enable --agent <name>` verb exists with the file-location matrix from ADR-0009's prior-art table documented, but only `claude-code` (Executor) and `langgraph` are wired. No CrewAI / Codex / Cursor / Gemini / OpenCode / Factory AI Droid / Copilot CLI impls in v1.1 unless a design partner explicitly pulls one — the verb is there so impls are a 50-line PR rather than an architectural decision.

A v1.1 release is **not** shippable on:

- "We added a backend but no one's using it yet." Adapters without usage are speculative; defer.
- "Promotion works in tests but no design partner has actually promoted an ephemeral run." That's a v1.0-style gap and we don't reproduce it in v1.1.
- "Hardening sprint follow-ups are 90% done." 90% means open kill-criteria still open; treat the same as v1.0.

## Workstreams

### Workstream 1 — Storage backend matrix

Owner: TBD (likely Toni until a second engineer).
Governing ADR: [ADR-0006](../adr/0006-objectstore-backend-trait.md).
Estimated effort: 4–5 weeks of focused work for the trait extension + S3 backend; +2–3 weeks if the first managed-Git adapter lands first instead of S3.

Milestones, in order:

- **W1.1.1** — Land `delete` and `list_prefix` on the `ObjectStore` trait. Implement on `FsObjectStore` and `GcsObjectStore`. Tests against both. *Closes ADR-0006 Action 1.*
- **W1.1.2** — Land `AsyncObjectStore` trait. Wire `GcsObjectStore` to expose it natively. Keep `FsObjectStore` blocking-only. *Closes ADR-0006 Action 2.*
- **W1.1.3** — Production-readiness validation for `GcsObjectStore`: concurrent writers, partial-upload failure injection at the ADR-0002 §3 2PC boundary, service-account auth, large-blob streaming. CI nightly. *Hardening sprint rollover.*
- **W1.1.4** — `S3ObjectStore` if AWS-resident design partner pulls. Roughly isomorphic to GCS; ~1 week porting + tests. If no AWS partner pulls, skip to W1.1.5.
- **W1.1.5** — `ManagedGitClient` trait and `ManagedGitStore` adapter. First impl chosen by design-partner ask. Code.Storage is one candidate; we don't pre-commit. *Closes ADR-0006 Actions 3 and 4.*
- **W1.1.6** — `agenticd` config schema for per-backend selection (`[object_store]` + `[object_store.<backend>]`). Docs at `docs/integration/object-store-backends.md`.

Gate (must hold before any backend ships): the LangGraph broken-prompt demo continues to pass with `FsObjectStore` as the default, with **no** environment variable changes from the v1.0 quickstart.

### Workstream 3 — Hardening rollover

Owner: TBD.

Milestones, in order:

- **W1.3.1** — Blob-level GC against `FsObjectStore` and `GcsObjectStore`. Orphan-detection via `list_prefix` (from W1.1.1). Two-phase reap: ref-layer cleanup happens first, blob-level GC reaps unreferenced objects on a second pass.
- **W1.3.2** — `agentic init` filesystem-snapshot-capability detection becomes a hard guard when `AGENTICD_DEPLOYMENT_MODE=production` is set. Informational warning remains the default. *Closes the ADR-0002 Decision 4 Action 4 follow-through.*

Gate: the v1.0 performance numbers (`commit < 2s`, `rollback < 5s`, `diff < 1s`, `write overhead < 5ms p99`, `snapshot storage < 2× changed data amortized`) from [`snapshot-model.md` §9](../architecture/snapshot-model.md) must not regress.

## Out of scope for v1.1 (will be asked about)

These come up enough that we list them explicitly here, not just in `roadmap.md`:

- **Adopting Code.Storage (or any managed-Git provider) as the substrate.** We adopt them as **one backend candidate** behind the `ObjectStore` trait, per [ADR-0006 Decision 3](../adr/0006-objectstore-backend-trait.md). The platform-API contract stays our `Commit` object. The substrate stays self-hosted-Postgres-plus-object-store by default. The boundary is hard.
- **Exposing managed-backend-specific primitives (Code.Storage's ephemeral branches, sandboxes, GitHub bidirectional sync) through our SDK or CLI.** Those are backend-specific features; access them via the adapter or via the provider's own tooling. Our SDK speaks `Commit` objects and ref names per [ADR-0002 Decision 6](../adr/0002-substrate-and-supercommit.md). If a design partner wants their managed-Git provider's ephemeral branches *as well as* ours, they run both — they don't get a unified ephemeral-branch abstraction in our SDK.
- **A second framework integration beyond LangGraph + Executor.** CrewAI / AutoGen / Codex / Cursor / Gemini / OpenCode / Factory AI Droid / Copilot CLI are v1.2+ unless a design partner explicitly blocks on one in v1.1. Workstream 4c ships the *verb and file-location matrix* so the impl is a 50-line PR rather than an architectural decision; it does not ship any of the impls themselves. The framework-neutral SDK contract from ADR-0003 Decision 3 is what makes that future work cheap; we don't preempt it.
- **The `agentic explain` verb.** Resist. Per [ADR-0009 Decision 7](../adr/0009-commit-time-narrative-summarization.md) the narrative is a Commit field, readable via `agentic show --narrative`, not a new top-level workflow surface. Entire ships `entire checkpoint explain`; we deliberately don't.
- **Per-object-kind routing policy DSL.** Per [ADR-0008 Decision 2](../adr/0008-secondary-objectstore-for-agent-state.md), the secondary-store routing rule is fixed: all agent-state objects route to secondary when configured. A per-kind policy language would be scope creep dressed as flexibility. Defer until a second design partner explicitly pulls.
- **Non-Anthropic LLM providers for summarization.** Per [ADR-0009 Decision 5](../adr/0009-commit-time-narrative-summarization.md) the v1.1 provider set is `anthropic_api`, `claude_cli`, `none`. OpenAI / local llama.cpp are 50-line additions behind the `Provider` trait when a design partner pulls; not in v1.1 scope.
- **A web UI.** v1.1 product surface candidate per ADR-0002 Decision 6, but not in this plan because it is not on the substrate path.
- **Hosted SaaS.** Post-seed per `roadmap.md`.
- **Eval / CI/AE pipeline.** Out of category per `mvp-spec.md`.

## Dependencies on v1.0

This plan assumes:

- The hardening sprint Week A items A1–A4 close before 2026-06-03 (cold-start demo, GCS un-`#[ignore]`, benchmarks, asciinema). If they don't, v1.0 ship is at risk and v1.1 timeline moves with it.
- The hardening sprint Week B items B1–B4 close before 2026-06-17 (sidecar image, TestPyPI SDK, design-partner pipeline, Executor harness check memo). Same.
- By v1.0 ship, ADR-0005 is Accepted (not Proposed), the `AgenticSessionStore` is in production for at least one Executor pilot, and per-session branches at `executor/<session_id>` exist as a live artifact to refactor.

If any of these slip, the v1.1 dates slip by the same amount. No catching up by cutting scope from this plan; cut from v1.2+ work instead.

## Open questions

These need resolution but are not blockers to opening the v1.1 workstreams:

- **Q1: Which is the first non-FS, non-GCS backend to ship — S3 or `ManagedGitStore`?** Depends on which design partner pulls first. Track in the design-partner pipeline.
- **Q2: Is the 14-day default TTL on ephemeral refs (ADR-0007 Decision 4) the right number?** Real value comes from pilot feedback. Reasonable bracket is 7–30 days.
- **Q3: Does `agentic promote` synthesise a Commit on the destination ref, or does it just write the ref pointer?** ADR-0007 Decision 3 says synthesise (for the `promote_of` attestation). Validate this against one design partner's mental model before locking it in.
- **Q4: Do we ship a CLI `agentic gc` subcommand, or is GC entirely a daemon background task?** Lean: subcommand for ops visibility; background task for the default path. Specify in W1.3.1.
- **Q5: How aggressively do we want to chase managed-Git providers as design partners themselves?** Pierre and any equivalent are commercially in the same lane as our long-arc positioning. Worth one conversation each post-v1.0 ship — outcome could be partnership, could be useful intel, could be "they're competitors we should outpace." Track separately from the engineering plan.
- **Q6: Is Entire (`entireio/cli`) a partner, a competitor, or both?** Today they're adjacent — they capture *why code changed*, we rewind *agent behavior*. Per [`competitive-brief-entire.md`](./competitive-brief-entire.md) we estimate a 12–18 month architectural lead at the substrate layer, but they're already at 4.3k stars and a defined category position. One conversation post-v1.0 ship. Outcomes worth considering: do nothing (most likely — we serve different needs), opportunistic integration (`agentic` reads from `entire/checkpoints/v1` for transcript ingestion when present), or — if their roadmap moves toward memory/schema rollback — flag in the next sprint review.
- **Q7: Is the `claude_cli` provider for summarization (ADR-0009) worth shipping in v1.1, or do we defer to the API-only path?** The argument for: it matches developer mental model when `claude` is already in `PATH`. The argument against: subprocess invocation + cold-start cost + transcript-egress-via-CLI is harder to reason about than a single API call. Bracket: lean ship in v1.1 with a clear "we recommend `anthropic_api` for production" note in the doc; revisit if it generates support load.

See [ADR-0006](../adr/0006-objectstore-backend-trait.md), [ADR-0007](../adr/0007-ephemeral-branches-agent-run-primitive.md), [ADR-0008](../adr/0008-secondary-objectstore-for-agent-state.md), [ADR-0009](../adr/0009-commit-time-narrative-summarization.md), [`competitive-brief-entire.md`](./competitive-brief-entire.md), and the v1.1 section of [`roadmap.md`](./roadmap.md) for the calendar view.
